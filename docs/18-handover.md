# Handover: starting on another account or another machine

**Purpose.** Everything needed to carry on with FMIP (brand: Stadiomind) from a
different Claude account, a different computer, or both, without losing work
or re-deciding anything. Written 2026-11-01 (T-1701); refreshed 2026-11-04 (T-1734) and 2026-11-11 (after the nine-package UI review).

**How to use it.** Read §1 to see where each piece lives. Then follow §2
(another account on the same computer) or §3 (another computer). Then give
the new session the prompt in §4. The repository is the memory (see
`06-session-handoff.md`). This file lists only what lives *outside* it and
how to bring that across.

**Companion files.**
- `03-project-map.md`: what each part is responsible for and how the parts connect.
- `17-file-index.md`: every file, one line each. It is generated by `node scripts/file-index.mjs`.
- `14-maintainer.md`: what only the maintainer can do.
- `09-deploy.md`: the server runbook.

## 2. Another Claude account, same computer

Nearly everything stays, because the repo, `E:\FMIP` and `.claude` are on the
disk, not in the account.

1. **Sign in** to the Claude desktop app with the new account. Open the Code
   tab on the folder `E:\FMIP\fmip`. The project key stays `E--FMIP-fmip`, so
   the memory in `%USERPROFILE%\.claude\projects\E--FMIP-fmip\memory\` is read
   as before.
2. **Artifacts and Docs (account-bound).** From the old account, share these
   with the new account's e-mail as **Editor** (never by public link: outside
   editors then lose write access). The list with URLs is
   `E:\FMIP\handover\artifacts.md`. In order of importance:
   - the decision desk;
   - the old project board (only until its cards are imported into the console);
   - the dashboard;
   - the agent team page;
   - the Stadiomind Design System and the Redesign canvas;
   - the Persian setup guide (Claude Docs).

   Pages built with a `db` keep their data only on their original URL. Rebuild
   one in the new account only if it cannot be shared.
3. **Connectors.** In the new account, connect Claude Docs and Google Drive
   again, if they are wanted.
4. **Scheduled tasks.** Open the app's Scheduled list and check the active
   tasks (§6.4) are there and enabled. Press "Run now" once on each recurring
   one so its permission mode is saved under the new account.
5. **Claude in Chrome.** Sign the extension in to the new account if it is used
   (needed, for example, for Cloudflare changes from the maintainer's own Chrome).
6. **GitHub stays `moarjmand`.** Check with `gh auth status`. The full path is
   `C:\Program Files\GitHub CLI\gh.exe` when `gh` is not on PATH.

## 3. Another computer

### 3.1 Install

| Tool | Version | Note |
|---|---|---|
| Git | any recent | |
| Node.js | 22 (`.nvmrc`); 24 also works | `corepack enable` gives pnpm 10.33.0 from `package.json` |
| Docker Desktop | recent | Postgres/Redis for local tests; start by hand (autostart is off on purpose) |
| Python | 3.12+ | only to run the model outside Docker; `scripts/model-backtest.sh` uses Docker |
| GitHub CLI `gh` | recent | `gh auth login` as `moarjmand` |
| Claude desktop app | latest | Code tab; Claude in Chrome extension if browser work in the maintainer's Chrome is wanted |

### 3.2 Repository

```bash
git clone https://github.com/moarjmand/fmip.git E:/FMIP/fmip
cd E:/FMIP/fmip
pnpm install
cp .env.example .env
docker compose up -d
bash scripts/check-dev-stack.sh
```

- When the npm registry cannot be reached directly, see `06-session-handoff.md`, constraint 2 (`scripts/dev-proxy.sh`).
- The local database needs `pnpm migrate up --no-check-order` when migrations arrive out of order.
- Build `@fmip/contracts` and `@fmip/ingestion` before typechecking the API.

### 3.3 Claude Code's memory and tasks

Copy from the old computer (or from `E:\FMIP\handover\`, §5):

- `%USERPROFILE%\.claude\projects\E--FMIP-fmip\memory\` →
  the same path on the new computer. The key is the folder path with `:` and
  `\` turned into `-`. A different folder gives a different key, so copy the
  memory into that key instead.
- `%USERPROFILE%\.claude\scheduled-tasks\` → the same path. Then open the
  Scheduled list in the app, check each task, and press "Run now" once on the
  recurring ones.
- `E:\FMIP\` entire (or at least `ops\`, `data-audit\`, `dashboard\`).

### 3.4 Server access

The agent reaches production only as `ssh fmip-prod '<command>'`.

- **Copy the old key.** The maintainer copies the private key and `~/.ssh/config`'s `Host fmip-prod` block themselves; an agent never handles private keys.
- **Or make a new key.** Run `ssh-keygen -t ed25519`. On the old computer, append the new public key to `~fmip/.ssh/authorized_keys` on the server, and remove it there when the old computer retires.
- The `Host fmip-prod` block (user `fmip`, `IdentitiesOnly`, `BatchMode`, keep-alives) is in `E:\FMIP\handover\ssh-config.txt`. It names the host but holds no key.

### 6.2 Rules that bite

- **Never edit production's `.env` through the agent.** The guard hook blocks reading, copying or appending to it, and printing container environments. Propose `.env` lines to the maintainer, or give the variable a compose default (as `CONSOLE_HOST` has).
- **Show real-data screenshots before any visible deploy.** Deploy only on the maintainer's approval.
- **Branches.** One task = one branch `t-<id>-<slug>` = one PR. Merge when CI is green.
- **Deploy.** `ssh fmip-prod 'cd /opt/fmip && git pull --ff-only && bash deploy/rollout.sh'`, then `bash deploy/check-setup.sh`.
- **New write routes.** Every new write route needs entries in the security spec's `PUBLIC_WRITES`, the rate-limit inventory, and the "Rate limits" section of `02-architecture.md`.
- **Health checks on the server.** A loopback curl to Caddy on the server answers 000, because only Cloudflare's addresses are allowed. Test inside the web container instead.
