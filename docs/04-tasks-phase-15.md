On 2026-11-19 the agents console and the agent team were reviewed from seven
sides (product, the team's effectiveness, the agent definitions, security, a
page-by-page inventory, video architecture, video tools and licences; the
papers are in `E:/FMIP/ops/reports/console-review-2026-11-19/`). The same day
the maintainer answered the coordinator's four questions in chat:

1. **Video:** Remotion on our own server (its free tier, no account, no
   purchase); first a short measurement of render time and memory, then the
   first three formats. AI-generated video of players, clubs or match moments
   is rejected (D-454).
2. **Console:** build all six improvements in the proposed order, each visible
   change approved on real-data screenshots before it is deployed (D-456).
3. **Agent team:** strengthen it, all of it, including the scheduled tasks'
   prompts and how often they run (D-457).
4. **A separate restricted SSH key for the console publisher:** prepare it and
   show it to him before anything is applied (D-455 point 10).

**Why "Phase 15".** The plan was asked for as "Phase 14"; `04-tasks-phase-14.md`
is the model-factors backlog (D-303, T-1646 to T-1661), so this one takes the
next free number.

**Where it starts.** The review's urgent fixes are already tasks with their
own pull requests and are **not repeated here**: T-1877 (#950, merged) and
T-1883 (#951, merged), and, still open on 2026-11-19, T-1878 (#944), T-1879
(#947), T-1880 (#945, #948), T-1881 (#949) and T-1882 (#946), all in
`04-tasks-phase-13.md`; the choices they made are recorded in D-455.
Everything below builds on them. Rows are numbered from T-1884.

**Rules for every row.** At most about six source files a task (CLAUDE.md
section 3); a row that names more is split before it is started. A row marked
**Visible** is built from the designer's mock-up, shown to the maintainer as
real-data screenshots (1440 px and 375 px, Persian console, light and dark)
and deployed only on his approval. A new write route goes into the rate-limit
inventory and `docs/02-architecture.md`, and every new command writes a
`console_audit` row with actor, time, reason and previous value (rule 10). A
migration takes a timestamp after the newest on `main` when it is written
(after `1765901888000` once #948 is merged). Agents advise and never act
(D-328, D-340, D-427 point 12): nothing here gives an agent a write to the
repository, the database or a social network.

The console today is a window with a few buttons: findings can be filtered
and never settled, a queued run has no prompt and no status, and the pages
look alive while the maintainer's computer is off. The six improvements below
are in the order the maintainer approved (`product.md`, T-new-1 to T-new-6).

`E:/FMIP/ops/reports/console-review-2026-11-19/design/` (`spec.md`,
`<n>-<feature>-<desktop or phone>[-dark].png`, real data from the snapshot of
2026-11-18); rows tagged «نمونه» there have no real data yet. Every row here
is **Visible** unless it says otherwise: built from the mock-up, shown as
real-data screenshots, deployed on the maintainer's approval.

**Decided by the maintainer on 2026-11-19, after he saw the mock-ups** (D-456
point 2): the six are built as drawn; «قبول» on a finding creates a task row
with a task id by itself; the teammate's account has the same powers as the
maintainer's everywhere in the console (triage, running agents, approving
visible deploys, an inbox that shows everything), except what D-427 already
fixes; a manual "run now" is capped at two runs per agent in 24 hours, on top
of the hourly ceilings (40 commands, 10 runs), and a failed run is never
retried by itself. **Still defaults pending his word** (D-456 point 3, marked

Honesty rules for all of them (rule 4 applied to the console): a state exists
on a page only if the computer or the server wrote it; a spinner or "running"
never appears without its source and time; whatever waits for the computer
says so and says when it last synced; a push body, a search result and a
scorecard never carry the withheld detail of a security finding (D-455
point 2).
